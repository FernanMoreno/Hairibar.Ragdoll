# E02 / E03 evidence status

## E02 - BehaviourBipedStagger

Status: Certified by the exact physical benchmark on 2026-08-15.

The Open sections below are dated historical investigation records. They
precede the final calibration and are superseded by the closure section at the
end of this document.

The package implements stagger and retains intermediate actuator tests, but no
single benchmark currently proves the full claim: physical push, sustained
RequiresStep, selected-foot/clip agreement, lift-off, swing, replant, improved
capture margin, no foot slip, no Unpinned transition, and return to Puppet.

`PhysicalPush_RequiresStepEventActivatesStaggerWithoutManualBeginStep` proves
only routing into Stagger. It is not assigned as E02's exact certification
test.

`StepRecovery` is an external test resource owned by the consuming game. Its
green actuator tests establish authored clip wiring only; they do not turn the
package claim into a production physics benchmark.

### Follow-up, 2026-08-14

`StepRecovery` now branches each directional state on the `StepSwingFoot` Int:
0 animates `foot_l`; 1 animates `foot_r`. The actuator tests now cover both
selected-foot values: Right must move RightTarget and Left must move LeftTarget,
rather than accepting a target clip for the opposite foot.

The attempted single E02 benchmark exposed an unresolved fixture limitation:
Puppet's RequiresStep event activates Stagger at the end of its fixed tick, but
the fixture's deficit is already stable when Stagger takes its first COM sample.
Further, its selected physical foot does not replant within the measured cycle.
Therefore no E02 end-to-end test was retained and E02 stays Open. The existing
physical test is explicitly scoped to selected-foot actuation, not replant or
recovery certification.

## E02 benchmark execution, 2026-08-14

The complete benchmark was implemented with all required assertions and run in
the package assembly. The measured failure is precise: the selected foot enters
the `Replant` phase but never produces physical ground contact. The trace
reported `minReplantY=-0.0742` and `maxSelectedY=0.1981`, while the fixture
ground is around `y=-1.1`. Increasing the swing pin weight to `0.8` did not
change that outcome. The benchmark is therefore marked ignored with an explicit
blocker so the normal package suite cannot silently certify or fail on an
environmentally uncalibrated fixture. E02 remains Open until the
`StepRecovery`/ground calibration makes contact observable and the benchmark
passes all final-state and no-slip assertions.

## Final verification, 2026-08-14

The package PlayMode assembly completed successfully after the contact-detector
change: 689 tests total, 688 passed, 0 failed, and 1 ignored. The sole ignored
case is `PhysicalPush_StaggerRecoveryBenchmarkProvesCompleteEpisode`, with the
explicit replant-contact blocker above. This is a green regression suite, not
E02 certification.

The selected-foot contact assertion now follows Unity's documented
`Physics.ComputePenetration` contract: it requires actual collider overlap and
returns the minimum separating translation. The measured gap is therefore valid
evidence that the `StepRecovery`/ground fixture is miscalibrated; replacing it
with a height threshold would weaken the claim and was deliberately rejected.
The push and target-evaluation paths are likewise based on Unity's documented
`Rigidbody.AddForce` impulse and `Animator.Update` APIs.

The official RootMotion PuppetMaster documentation was used to preserve the
semantic boundary around `BehaviourPuppet.Unpin`, `Reset`, and explicit
`PuppetEvent.switchToBehaviour` transitions. It supports the lifecycle trace,
but does not document Hairibar's custom capture-point or foot-replant formulas.

## Final E02 closure and catalog alignment, 2026-08-15

The fixed-tick trace isolated the apparent horizontal failure. The benchmark
was recording the neutral `StepSwingFoot=0` parameter on the Stagger activation
tick, before the first real `LiftOff` phase selected the right foot. It also
showed that directional state names cannot be used as foot identity.

The runtime now prefers the layer-qualified Animator state path and, when
available, resolves the explicit `<direction>RightFoot` branch before the
parameter fallback. The actuator tests assert the selected foot and moved
target, not a hard-coded directional state name. The generated fixture retains
the authored local baselines and the corrected `AnimationClip.SetCurve` timing.
The benchmark measures selected-foot stride separately from residual physical-
to-target landing error, so the stride is not mislabeled as slip.

Contact is observed during Replant in the final run using the documented
`Physics.ComputePenetration` overlap check. The benchmark passed with
`marginBefore=0.1500`, `minimum=-0.0456`, `final=0.1500`, `selectedFoot=1`,
`selectedTravel=0.2038`, `selectedLandingError=0.0000`, `stanceTravel=0.0000`,
return to Puppet, and no Unpinned transition.

The package PlayMode focus passed 5/5, including the exact benchmark
`E02_PhysicalPush_StaggerRecoveryBenchmarkProvesCompleteEpisode`. Catalog and
closure-premature-count checks passed 4/4 EditMode, and the exact E03 settings
contract passed 1/1 PlayMode. CODE RED `propJoint` remains an external consumer
boundary and is not changed by this package certification.

## Sustained RequiresStep trace, 2026-08-14

The first run of the per-fixed-tick diagnostic with a two-sample
`MinimumRequiresStepDuration` did not reach the horizontal recovery assertion.
The observed samples were:

- tick 0: active `RagdollPuppetBehaviour`, `Stable`, margin `0.1500`, capture
  point approximately `x=0.08`, physical feet `x=0.00/0.50`;
- tick 1: active `RagdollBipedStaggerBehaviour`, still `Stable`, margin
  `0.1492`, capture point `x=0.00`, no step phase;
- tick 2: active `RagdollPuppetBehaviour`, `Stable`, margin `0.1492`, no step
  phase.

This run therefore proves neither sustained `RequiresStep` nor recovery. It
also exposes a fixture boundary: Puppet owns separate serialized
`staggerStableMargin`/`staggerRequiresStepMargin` fields from Stagger's public
thresholds. The fixture now aligns those two threshold pairs before the next
run. The trace is being extended with root position and velocity so the next
result can distinguish lost impulse/physical authority from capture-point or
Animator timing. No curve inversion, impulse relaxation, or margin assertion
change is justified by this run.
